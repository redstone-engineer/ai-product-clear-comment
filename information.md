### Чек-лист готовности проекта:

| Этап | Что проверить | Сделано? | Комментарий |
| :--- | :--- | :---: | :--- |
| **A. Постановка** | Задача чётко сформулирована (вход/выход) | **Да** | Вход: текст сообщения (str). Выход: вероятность токсичности (0.0-1.0) и класс безопасности (0/1). |
| | Baseline недостаточен (есть конкретные проблемы) | **Да** | Базовый RegEx/стоп-слова не улавливают завуалированную агрессию и контекст, допуская высокий процент False Negatives. |
| | Выбран способ адаптации (fine-tune/RAG/prompt/agent/CV) | **Да** | Выбран Fine-tune гибридной архитектуры (замороженный эмбеддер RuBERT + обучаемая BiLSTM-голова). |
| **B. Данные** | Источник легален, очищен, размечен | **Да** | Проведена глубокая очистка и валидация промышленного датасета объемом 500 000 русскоязычных комментариев. |
| | Есть train/val/test split (без утечек) | **Да** | Данные разделены с использованием `stratify` для сохранения пропорции классов. Валидационная выборка составила 15 763 объекта. |
| | Нет персональных данных без разрешения | **Да** | Все комментарии полностью деперсонализированы, ID авторов стерты, утечки личных данных исключены. |
| **C. Эксперимент** | Зафиксирована версия baseline | **Да** | В качестве Baseline зафиксирована базовая модель RuBERT со стандартным пулингом без использования последовательных слоев. |
| | Зафиксированы гиперпараметры/промпты/модель эмбеддингов | **Да** | Эмбеддер: `DeepPavlov/rubert-base-cased`. Фиксированный размер батча: 64. Оптимизатор: AdamW. Введен штрафной множитель для токсичного класса. |
| | Сохранены артефакты (веса, конфиги, логи) | **Да** | Веса обученной LSTM-головы (~10 МБ) сохранены в `.pth`. Веса базового BERT разделены для экономии VRAM. |
| **D. Оценка** | Есть eval-set (≥20 тестовых кейсов) | **Да** | Тестовый сет содержит более 15 тысяч реальных сообщений из СНГ-сегмента. |
| | Есть количественные метрики (accuracy, F1, hit@k, win-rate, latency, cost) | **Да** | Достигнуты SOTA-метрики: **Accuracy = 0.99**, **F1-score для токсичного класса = 0.97** (Precision: 0.97, Recall: 0.97). |
| | Есть качественные примеры «до/после» (3-5 штук) | **Да** | Собраны ложные срабатывания (88 FP) и пропуски (96 FN) для анализа краевых кейсов (Edge Cases). |
| **E. Интеграция** | Inference-скрипт или API готов | **Да** | Создан легковесный асинхронный пайплайн инференса (Раздельный прогон через RuBertEncoder и ToxicLstmHead). |
| **E. Интеграция** | Backend может вызвать модель | **Да** | Бэкенд на FastAPI полностью интегрирован с асинхронным драйвером MongoDB (`motor`) и ботом на `aiogram`. |
| | Frontend показывает результат и уверенность/источники | **Да** | Разработана админ-панель внутри Telegram Mini Apps для разметки False Positives и тонкой настройки порогов чата. |
| **F. Защита** | Можем объяснить, что именно адаптировали | **Да** | Адаптировали способ извлечения признаков: заменили линейные слои внимания на BiLSTM поверх всех скрытых слоев BERT. |
| | Можем показать прирост метрик (цифры) | **Да** | За счет подбора множителя наказания дисбаланса классов метрика F1-score до стабильных 0.97. |
| | Есть 2-3 ярких демо-кейса | **Да** | Проект развернут локально с автоматическим туннелированием через `pyngrok` (HTTPS) для живой демонстрации Mini App в ТГ. |
